# 搜索 / AI 工具详细对比（参考）

> 各家套餐和限额变动频繁，以下按"定位和能力"对比；执行前先确认额度以官网/客户端显示为准。
> 本文件是 `SKILL.md` 里"角色 → 可替换工具"表的展开。**四个环节（拆分/搜索/总结/成稿）是角色，不是工具名**：换 harness、换工具时按角色特征对号入座，不要照搬下面的具体产品。

## 两大类产品

- **检索类**（秘塔、DeepSeek 网页版内置搜索、Kimi 搜索、必应/百度、以及 harness 内置的 `web_search`）：先搜索再生成，答案带引用可溯源。解决"信什么"。
- **对话类**（ChatGPT、DeepSeek、Kimi 聊天）：回答主要来自模型自身知识，搜索只是其中一项功能。解决"怎么加工"。
  - 注意：对话类不勾联网就是靠记忆答，有幻觉风险；"帮我查 XX"在检索类里自动触发搜索，在对话类里默认不触发。

## 按角色选工具（主线）

| 角色 | 首选特征 | 可替换的候选 | 备注 |
|---|---|---|---|
| ① 拆分 | agent 自己 | 外部对话模型（DeepSeek / Kimi / ChatGPT 网页版） | 拆得动就自己拆，不转手 |
| ② 搜索 | **带引用摘要的检索** | harness 内置 `web_search` / 秘塔 / 必应 / 百度 | 见下方"搜索源选择" |
| ③ 总结 | 长文整理 | ChatGPT / Kimi / agent 自己 | 只有材料 > 5 篇或要成文报告才开 |
| ④ 成稿 | agent 自己 | — | 不转手 |

**没有秘塔直连的 harness**（如 DSH）：② 直接用 `web_search` 检索 + `read_page` / `web_fetch` 抓原文，③ 默认 agent 自己建目录式索引。别因为"缺某个工具"就跳过搜索环节。

## 搜索源选择（② 的细则）

| 搜索源 | 优点 | 缺点 | 什么时候用 |
|---|---|---|---|
| **秘塔** | 中文覆盖面大、一次检索直接回带引用摘要，比逐页抓**省 token** | 小众社区/论坛（酷安这类）索引差，搜不到 ≠ 不存在 | **中范围及以下的首选**；"不是非搜不可、只想更新信息"也用它 |
| **必应** | 泛探索广 | 引用质量参差 | 盲搜 / 泛探索 |
| **百度** | 百科、商品参数、论坛帖、国内官网 | 不能盲搜 | **只在明确指定查找时**用 |
| **harness 内置 web_search** | 一行调用、结果合并、无需用户操作 | 无深度研究模式、引用摘要不如秘塔完整 | 无法程序化访问秘塔/必应时的默认路线 |

**秘塔深度搜索**：一天限次。只有"子问题 ≥ 3 且值得出报告"才开，普通搜索够用就别开。

**agent 侧只拿 URL**，之后 `web_fetch` / `read_page` 抓内容；结果页抓不动也别死磕，换信源。

## 各网页端工具优缺点（agent 选路 / 回答用户"用哪个"时参考）

**秘塔（metaso.cn）**
- 网页版：✅ 普通搜索免费无硬限，引用逐条可点、溯源最严；**范围广**（中文网页覆盖面大），一次检索直接回带引用摘要，比 agent 逐页抓内容**省 token**；最合适的场景是"**不是非搜不可、只是想更新一下信息**"；❌ **小众社区/论坛（酷安这类）索引覆盖差，搜不到不代表不存在**，要查就直抓目标站；❌ 无公开 API、结果页 JS 渲染，agent 抓不动 → 只能人工搜后贴结果/摘要，或用浏览器自动化操作

**DeepSeek（chat.deepseek.com）**
- 网页内置搜索：✅ 免费放开、能多轮追问；❌ 索引广度和时效一般，引用宽松 → 只当粗筛快查，结论要再拿秘塔/原文复核。深度思考模式（网页版免费）用于材料矛盾裁决

**Kimi（kimi.moonshot.cn）**
- 网页版：✅ 超长文档摘要招牌、搜索也免费；❌ 无自动化途径，靠人操作

**ChatGPT（chatgpt.com，需 VPN）**
- 网页版（需 VPN）：✅ 多语言归纳/报告强（含中英互转），免费版轻量模型日常够用；❌ 深度研究（Deep Research）和高级模型限次/需 Plus

**必应**
- 浏览器：✅ **盲搜、泛探索**可以直接用（没想好搜什么词也没关系），英文资料也好使；❌ 结果页对 agent 抓取不友好 → agent 侧做法是"搜索只用来找 URL，拿到 URL 后抓内容"，不试图抓结果页本身

**百度**
- 浏览器：✅ 只在**明确指定**查找时用——百科条目、商品参数、论坛帖、国内官网入口；❌ **不能拿来做盲搜**，搜什么还没想清楚就换必应

**通用规律**：多数工具的搜索能力在网页/App 端，agent 侧的检索通常是"找 URL → 抓内容"一条路；归纳这步要么 agent 自己做（材料少，默认），要么用户在网页版做（材料多）。

## 组合用法（角色视角，默认流程）

1. **拆分**：agent 自己把大范围目标拆成 3~6 个中范围子问题（外部模型只是平替）。
2. **搜索**：每个子问题各搜一轮，拿到带引用的材料。搜索源按上表选；子问题 ≥ 3 且值得出报告时才开秘塔深度搜索（限次省用）。
3. **总结**：材料 > 5 篇或用户要成文报告才开：整理成 agent 好取用的**目录式**中间产物（先总结所有搜索内容，再给完整内容目录：哪部分/哪段讲什么 + 来源链接）；连接不稳时换平替。材料少就 agent 自己建索引，省额度。
4. **成稿**：agent 按目录组合结论、标注来源；材料 < 3 篇时跳过 ①③，agent 自己归纳（推荐，非硬性——看具体情况）。
5. 产出带引用的结论；无法核实的单独列"未验证"一节。

## 额度红线

- 秘塔普通搜索免费放开；**深度搜索一天限次**，只有"子问题 ≥ 3 且值得出报告"才开
- ChatGPT 免费版轻量模型够用，不为深度研究烧额度
- 归纳整理活 agent 能自己做就不转手
- harness 内置 `web_search` 同样按次计费：能合并的 query 合并（一次 1~4 条），别一条一条打
