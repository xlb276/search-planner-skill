# 研究搜索：工具选择 + 执行流程

## 什么时候用 / 不用

- **有大概目标、需要搜**（"查一下 XX 情况"、"调研 XX"、"XX 方案有哪些"）→ 用本 skill
- **已知具体网址/目标页面** → **不用本 skill**，直接 WebFetch 抓那个页面；任务里既有已知又有未知的，已知部分直接抓，只对未知部分走搜索流程
- 拿不准就按"需要搜"处理，搜索范围自然会收窄

## 推荐管线（默认路线）

**最推荐：秘塔**（引用最严），最适合**中范围及以下**的搜索。大范围任务走这条管线（其中模型指派是示例映射，可替换，见"模型可替换"节）：

```
大范围目标
  ① DeepSeek 网页版（免费，或 Kimi 平替）：把大范围拆成多个中范围子问题，可追问确认拆得对不对
        ↓
每个子问题 → ② 秘塔搜索（中范围最适；子问题 ≥ 3 个才考虑开秘塔深度搜索，免费版限次省着用）
        ↓
搜索材料 → ③ 总结：ChatGPT 网页版整理成 agent 好取用的中间产物。**推荐目录式**：先给所有搜索内容一个总结，再给出对应 AI 搜索出来的完整内容的目录（哪部分/哪段讲了什么、来源链接），agent 按目录按需取用；具体形式仍看情况
        ↓
④ agent 按索引成稿：组合结论、标注来源、输出
```

**平替与下位替代规则（每环可换谁）：**

| 环节 | 首选 | 平替（优先级相同，按优缺点选） | 下位替代（首选不可用/不稳时才用） |
|---|---|---|---|
| ① 拆分 | DeepSeek | Kimi | — |
| ② 搜索 | 秘塔 | **无平替**（中范围及以下搜索只有秘塔最合适） | — |
| ③ 总结 | ChatGPT | Kimi | 连接不稳定时 Kimi 是 ChatGPT 的主场景 |
| ④ 成稿 | agent 自己 | Kimi（转网页版代劳时） | 同③ |

- 选平替时看 `references/tools-comparison.md` 的优缺点：长文档摘要 Kimi 最稳、中英互转/报告 ChatGPT 最强、矛盾裁决 DeepSeek 深度思考

**补充路（不占管线位置）：**

- **必应**：盲搜/泛探索直接用它；**百度**：只在明确指定查找时用（百科、商品参数、论坛帖、国内官网），不能拿来做盲搜
- agent 侧只拿 URL，之后 WebFetch 抓内容；结果页抓不动也别死磕

## 跳过规则（推荐，不是硬性）

**本节所有规则都是推荐**，最终由 agent 按具体情况自行判断。判断时综合看：子问题数、材料实际量、**用户的 token 余量（额度紧张就多做少转手，额度宽裕就放宽）**、各工具剩余配额、任务时限、用户偏好：

- 子问题 ≤ 2 个或材料 < 3 篇（推荐）→ 跳过 ①③，秘塔搜完 agent 自己整理（默认，不烧额度）
- ChatGPT 连接不稳/不可用 → ③ 改 Kimi（这是 Kimi 的主要使用场景）；用户连网页版都不想开 → agent 直接整理全量材料
- 只有 1 个子问题且范围小 → 直接 ② 一步到位
- 跳过后材料量超出 agent 自己整理的合理范围，再建议用户开对应环节补上

## 模型可替换（按角色映射，不锁定具体模型）

管线四个环节是**角色**（能力需求），不是模型名：

| 角色 | 能力需求 | 当前示例映射 |
|---|---|---|
| ① 拆分 | 把宽问题拆成可检索子问题，支持追问确认 | DeepSeek / Kimi |
| ② 搜索 | 带可点引用的搜索，中范围及以下 | 秘塔 |
| ③ 总结 | 长文整理、产出 agent 好取用的中间产物 | ChatGPT / Kimi |
| ④ 成稿 | 组合材料、标注来源 | agent 自己 |

本 skill 里所有模型指派（管线、平替表、额度规则）**都只是当前推荐示例，不是硬性规定**。换模型、新出模型时：按上表角色特征评估后塞进对应角色即可，不用改 skill；`references/tools-comparison.md` 里也没有的新工具，同样按角色特征判断能不能顶替。

## 通用性说明（任何 harness 都用）

本 skill 是**通用 skill**，不绑定任何具体 harness/工具集。执行前先摸一遍当前环境有什么（WebFetch？浏览器/browser-use？各模型网页版用户能不能开？），然后：

- 角色都能落实 → 按管线走
- 有角色落实不了（比如 harness 里没有途径执行 ② 搜索）→ **agent 自己加一段"专属段"**：写清"本 harness 下各角色怎么落实 + 本次降级方案"（如 ② 退成 agent 用 WebFetch 直抓已知站点、③ 退成 agent 自己总结）。有持久化位置（工作区笔记、记忆文件）就写进去，下次直接复用；没有就写在本次产出开头。
- 降级顺序：尽量保住输出要求（带引用的结论、未验证标注）再牺牲中间环节，别反过来

## 各途径优缺点与额度规则

各工具（网页端）的详细优缺点在 `references/tools-comparison.md`，选路拿不准、用户问工具区别时先读它。额度红线：

- 秘塔普通搜索免费放开；**深度搜索一天限次**，只有"子问题 ≥ 3 且值得出报告"才开
- ChatGPT 免费版轻量模型够用，不为深度研究烧额度
- 归纳整理活 agent 能自己做就不转手

## 输出要求

- 结论按子问题组织，每条论断附 `[来源](url)`
- 信源冲突明写"X 说 A、Y 说 B"，不擅自裁决（拿不准就开 DeepSeek 深度思考裁决）
- 无法核实的单独列"未验证"一节
- 一句话总结放最前面
